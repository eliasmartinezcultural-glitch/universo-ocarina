# Ocarina Lab · Ciclo de vida de producto 1.0

## Principio

Un producto no es una idea en el catálogo. Es un activo terminado que puede encontrarse, verificarse, fabricar sus salidas y entregarse sin rehacer el trabajo.

## Estados

`IDEA → LAB → QA → AVAILABLE → ARCHIVED`

### IDEA
Concepto todavía no producido.

### LAB
En fabricación o experimentación. No vender.

### QA
Tiene una fuente y está siendo controlado.

### AVAILABLE
Tiene nombre, SKU, fuente válida, descripción, reglas de uso y salida comercial PDF/JPG. Puede ofrecerse.

### ARCHIVED
No vender. Se conserva como historial si corresponde.

## Gate de publicación

Antes de pasar a `AVAILABLE`:

- [ ] SKU único.
- [ ] Nombre claro.
- [ ] Familia definida.
- [ ] Fuente maestra existente.
- [ ] Integridad factual revisada cuando el producto contiene datos reales.
- [ ] Fotografía propia/autorizada si corresponde.
- [ ] Marca Ocarina pequeña.
- [ ] PDF probado.
- [ ] JPG probado.
- [ ] Nombre de archivo correcto.
- [ ] El comprador no recibe fuentes internas.
- [ ] Precio de referencia definido internamente.

## Regla de reutilización

Cada obra terminada debe evaluarse para convertirse en otros productos:

`FOTO → POSTAL → LÁMINA → PÓSTER → PACK → REDES`

`INVESTIGACIÓN → GUÍA → MAPA → LÁMINA → PACK`

`MAPA VERIFICADO → MAPA ARTÍSTICO → RUTA → GUÍA`

Esto convierte la fábrica en un sistema acumulativo: cada hora de trabajo aumenta el inventario futuro.

## Regla comercial

La fábrica debe optimizar el tiempo entre:

**PEDIDO → PRODUCTO → QA → ARCHIVO FINAL → WHATSAPP**

No debe agregar pantallas, formularios o bases de datos que no reduzcan errores o tiempo.

## Seguridad editorial

GitHub Pages es un escaparate público, no una bóveda privada. Los materiales sensibles, originales privados y datos de compradores no deben almacenarse allí.
