# Ocarina Lab · Protocolo de calidad territorial

## Objetivo

Que la fábrica pueda producir mucho **sin bajar la calidad**.

La investigación territorial se trata como una base de datos editorial, no como una lista improvisada de enlaces.

## Regla de oro

**Descubrir no es verificar.**

Google Maps/Places, OpenStreetMap, Tripadvisor, blogs, Instagram y directorios son excelentes para descubrir negocios, caminos, cambios y pistas. No deben convertirse automáticamente en hechos oficiales.

## Pirámide de evidencia

### A — Primaria/oficial
Municipalidad, Provincia, Catastro, COPADE, Turismo Neuquén, organismos públicos, documentación del propio establecimiento.

Uso: hechos, ubicación oficial, infraestructura, habilitaciones cuando estén explícitas, historia institucional, datos territoriales.

### B — Institucional/sectorial
Entidades vitivinícolas, organismos de promoción, cámaras, publicaciones sectoriales, medios oficiales de organismos.

Uso: contexto productivo, enoturismo, gastronomía, actividad económica.

### C — Comunitaria/dinámica
Google Maps/Places, OpenStreetMap, Tripadvisor, redes sociales, directorios y reseñas.

Uso: descubrir, detectar cambios, encontrar nombres, revisar experiencia de usuarios, localizar entidades no presentes en fuentes oficiales.

### D — Secundaria débil
Blogs antiguos, agregadores sin fecha, publicaciones sin autoría o procedencia clara.

Uso: generar pistas que luego deben corroborarse.

### E — Ocarina
Relevamiento propio, fotografía propia, interpretación artística o síntesis editorial.

Debe identificarse claramente como producción Ocarina.

## Ficha mínima de cada entidad

Cada prestador/lugar debería poder registrar:

- nombre
- categoría
- ubicación textual
- coordenadas cuando estén verificadas
- fuente primaria
- fuente secundaria
- URL
- fecha de última verificación
- estado: confirmado / requiere verificación / cerrado / histórico / temporal
- servicios
- horarios
- contacto
- redes
- reservas
- temporada
- nivel de confianza
- observaciones editoriales

## Control para mapas

1. Separar cartografía oficial de cartografía colaborativa.
2. No inventar calles, picadas, barrios, límites o coordenadas.
3. Si una geometría procede de OSM, registrarlo.
4. Si procede de Catastro/Provincia, registrarlo.
5. Si es una interpretación artística, rotularla como tal.
6. No presentar un mapa ilustrado como navegación exacta.
7. Las rutas rurales requieren verificación adicional porque pueden cambiar de condición o no ser de acceso público.

## Control para guías

Antes de publicar una guía de prestadores:

- revisar existencia
- revisar nombre
- revisar ubicación
- revisar actividad
- revisar contacto
- revisar horario
- revisar modalidad de reserva
- revisar habilitación si se afirma que está habilitado
- registrar fecha de corte de la edición

## Control de datos dinámicos

Horarios, precios, teléfonos, redes, reservas, disponibilidad, menú, servicios y estado comercial pueden cambiar rápidamente.

La guía debe incluir una **fecha de actualización** y, cuando corresponda, una frase del tipo:

> "Datos verificados hasta [fecha]. Se recomienda confirmar horarios y disponibilidad antes de viajar."

## Calidad comercial

Un producto puede ser bonito y estar mal investigado. En Ocarina eso no alcanza.

El estándar buscado es:

**bonito + útil + verificable + trazable + actualizado + territorialmente honesto.**

## Regla de publicación

No publicar una afirmación como definitiva si el sistema solo posee una pista.

Cuando exista incertidumbre, decirlo.

La transparencia aumenta el valor del producto; no lo disminuye.
